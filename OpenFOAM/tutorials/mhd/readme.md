# Tutorials & Examples (Work in Progress)

This directory contains example cases to demonstrate the setup of the inductionless MHD solvers. 

## ⚠️ Disclaimer
The original cases (`duct`, `duct_hartmann_conductive`, `duct_heated`, ...) are **functional examples** intended to demonstrate dictionary setups and boundary conditions. The [validation cases](#validation-cases) below are checked against analytical solutions.

### Standard Potential Solvers

*   **`epotFoam_isoTh`**: Isothermal inductionless MHD solver. Focuses on the coupling between the Navier-Stokes equations and the electric potential ($\phi$) formulation for Lorentz force calculation.
*   **`epotFoamBuo`**: Buoyant inductionless MHD solver. Incorporates Boussinesq or coupled density-driven flows, specifically designed for magnetoconvection studies.

#### Conjugate Solvers (Arbitrary Conductivity)
*   **`cEpotFoam`**: A conjugate solver designed to handle **arbitrary electrical conductivity** across the fluid-solid interface.
*   **`cEpotBouyantFoam`**: The buoyant counterpart to `cEpotFoam`, used for complex magnetoconvection scenarios in geometries with conductive walls.
*   **`cEpotBouyantBulkFoam`** `[Experimental]`: Extension of `cEpotBouyantFoam` featuring variable bulk temperature formulations.

## Validation cases

Laminar, fully developed cases with analytical solutions from the literature. Each case runs with `./Allrun` and ends with `validate.py`, which prints the errors against the analytical solution, writes `validation.png`, and exits non-zero on failure. Parameters live in `system/caseParameters` and are regenerated by `setup.py` (for example `HA=500 ./Allrun`). All cases are non-dimensional (a = ρ = ν = σ = ū = 1, so B = Ha).

**G** is the mean streamwise pressure gradient −dp/dx needed to drive the bulk velocity ū, given as G a²/(ρ ν ū). a is the half-height, half-width or radius. It is the headline number of each validation, a global measure of MHD drag. With no magnetic field it would be 3 (channel), 7.11 (square duct) or 8 (pipe).

| Case | Solver | Reference | Tests | Error in G (default) | Run time |
|---|---|---|---|---|---|
| [`hartmann_channel`](epotFoam_isoTh/hartmann_channel) | `epotFoam_isoTh` | Hartmann (1937) | 1D Hartmann layers; insulating or shorted | 0.53 % (Ha 50) | 1 s |
| [`shercliff_duct`](epotFoam_isoTh/shercliff_duct) | `epotFoam_isoTh` | Shercliff (1953) | Square duct, insulating walls, side layers | 0.59 % (Ha 100) | 1.5 min |
| [`hunt_duct`](cEpotFoam/hunt_duct) | `cEpotFoam` | Hunt (1965) | Thin conducting Hartmann walls, side jets | 0.18 % (Ha 100, c 0.1) | 2 min |
| [`thick_wall_duct`](cEpotFoam/thick_wall_duct) | `cEpotFoam` | exact thick-wall solution; cf. Bluck & Wolfendale (2015) | Thick conducting walls, potential inside the wall | 0.26 % (Ha 100) | 2 min |
| [`pipe_insulating`](epotFoam_isoTh/pipe_insulating) | `epotFoam_isoTh` | Gold (1962), Shercliff (1956) | Circular pipe, O-grid (non-orthogonal) | 0.42 % (Ha 100) | 2 min |
| [`pipe_conducting`](cEpotFoam/pipe_conducting) | `cEpotFoam` | exact thick-wall solution; cf. Chang & Lundgren (1961) | Conducting annular wall, curved interface | 0.07 % (Ha 100) | 2 min |

The pipe cases need `gradSchemes leastSquares` and a time-step cap on the O-grid. Their readmes explain why.

Buoyant cases have zero net flow, so their headline number is the peak velocity, not G:

| Case | Solver | Reference | Tests | Error in u_max (default) | Run time |
|---|---|---|---|---|---|
| [`buoyant_slot`](epotFoamBuo/buoyant_slot) | `epotFoamBuo` | exact buoyant Hartmann profile | Solver's own `p_rgh` buoyancy, closed tall slot, ∇T ∥ B | 0.002 % (Ha 20) | 30 s |
| [`buoyant_duct_insulating`](epotFoamBuo/buoyant_duct_insulating) | `epotFoamBuo` | exact series; cf. Authié, Tagawa & Moreau (2003) | Vertical duct, ∇T ⊥ B or ∥ B (`HEATING=`) | 0.51 % / 0.44 % (Ha 100) | 4.5 / 2.3 min |
| [`buoyant_duct_conducting`](cEpotBuoyantFoam/buoyant_duct_conducting) | `cEpotBuoyantFoam` | exact series, thick walls | Conjugate electric and thermal coupling, both orientations | 0.44 % / 0.58 % (Ha 100) | 2.5 min |
| [`hadley_cavity`](epotFoamBuo/hadley_cavity) | `epotFoamBuo` | exact parallel-flow core; cf. Garandet, Alboussière & Moreau (1992) | Horizontal cavity, vertical B: **heat transport by the flow** (T advection) | 0.005 % (θ: 0.06 %) (Ha 20) | 2 min |

The buoyant ducts are periodic in the vertical direction. That is incompatible with a periodic `p_rgh`, so their buoyancy is a coded body force. `buoyant_slot` covers the solvers' own buoyancy term.

**Scope and limitations.** These cases check that the solvers reproduce known solutions, for the listed meshes and parameters in OpenFOAM v2606. They are not a comparison with experiments. Some reference solutions (thick-wall duct, conducting pipe, buoyant ducts) were derived here and checked against limiting cases and independent numerical solutions, but not against published data. Errors in the references or scripts are still possible; please report any you find.

[`common/`](common) holds the shared Python code:
- `mhdAnalytic.py`: Hartmann and duct series solutions (pressure-driven and buoyant) for insulating, thin, thick and perfectly conducting walls
- `pipeAnalytic.py`: spectral pipe solution (insulating, thin or thick conducting wall) and the closed-form Gold-type check
- `ductValidation.py`, `conductingDuct.py`, `pipeCase.py`, `buoyantDuct.py` and `zhengDuct.py`: comparison, plotting and case setup
- `foamCase.py`: ASCII field reader, mesh grading, parameter files

The scripts find `common/` through the relative path `../../common`. If you copy a case elsewhere, set `MHD_COMMON=/path/to/common`. They need Python 3 with numpy; matplotlib is optional and used for the plots.
